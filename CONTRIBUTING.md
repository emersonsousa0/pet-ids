# Guia de Contribuição — PET IDS

Este documento estabelece as orientações para contribuir com o projeto de detecção inteligente de ameaças.

## 1. Organização das branches

A branch principal do projeto será a `main`.

Novas funcionalidades, correções e documentações devem ser desenvolvidas em branches separadas.

Padrões de nomenclatura:

- `feature/nome-da-funcionalidade` — novas funcionalidades.
- `fix/nome-da-correcao` — correções de problemas.
- `docs/nome-da-documentacao` — alterações na documentação.
- `test/nome-do-teste` — criação ou alteração de testes.

## 2. Fluxo de trabalho

1. Atualizar a branch principal antes de iniciar uma atividade.
2. Criar uma branch específica para a tarefa.
3. Desenvolver e testar as alterações.
4. Enviar a branch para o GitHub.
5. Abrir um Pull Request direcionado à `main`.
6. Solicitar a revisão de outro integrante.
7. Realizar os ajustes solicitados.
8. Aguardar pelo menos uma aprovação antes do merge.

## 3. Pull Requests

Todo Pull Request deve:

- Possuir um título claro e objetivo.
- Descrever as alterações realizadas.
- Informar a tarefa relacionada, quando houver.
- Apresentar evidências de testes, quando aplicável.
- Estar aprovado por pelo menos um integrante.
- Ter todas as conversas de revisão resolvidas.

## 4. Boas práticas

- Não realizar alterações diretamente na `main`.
- Evitar commits com várias alterações sem relação entre si.
- Utilizar mensagens de commit claras.
- Não enviar senhas, tokens ou informações confidenciais ao repositório.
- Manter o código e a documentação organizados.
- Comunicar conflitos ou dificuldades à equipe.

## 5. Integração contínua

O projeto utilizará integração contínua (CI) para executar verificações automáticas, incluindo lint e testes de fumaça.

As ferramentas e os comandos serão definidos após a escolha das tecnologias utilizadas pelo projeto.
